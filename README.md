# pinger

Мониторинг доступности хостов: сервис пинга через
[`fping`](https://fping.org/) + веб-интерфейс на FastAPI + Jinja2 + HTMX +
Bootstrap 5. Одна SQLite-база, два процесса: сервис пинга (пишет статусы и
историю) и веб (читает статусы, управляет конфигурацией).

## Возможности

- Батч-опрос всех адресов одним процессом `fping` раз в `round_interval_s`.
- История доступности как интервалы up/down + uptime % (за 24 ч на чипах,
  за произвольный диапазон на экране адреса).
- Страницы → строки → адреса; страница и адрес можно временно выключить.
- Роли и права: `admin` / `user` с режимами видимости `all` / `except` /
  `only` и постраничным правом редактирования.
- Веб: просмотр и редактирование — отдельные режимы; добавление — через
  модальные окна; автообновление статусов через JSON без мигания.
- Cookie-сессии, argon2, CSRF-токены; первый админ создаётся через `/setup`.

## Быстрый старт (Docker)

Требуется Docker с `docker compose` v2.

```bash
make docker-up          # собирает образ и поднимает pinger + web
make docker-logs        # логи
make docker-down        # остановить
```

Откройте `http://localhost:8000`. Пока в базе нет активного администратора,
единственная доступная страница — `/setup`: создайте первого админа
(если задан `PINGER_SETUP_TOKEN`, его нужно ввести там же).

База и конфиг лежат в `./data` (том `./data:/app/data`, в git не попадает).

## Быстрый старт (без Docker)

Требования: Python 3.14, [`uv`](https://docs.astral.sh/uv/), `fping` в
`PATH` (`apt install fping`), для ICMP-сокетов нужен `NET_RAW`
(обычный пользователь — через `setcap cap_net_raw+ep $(which fping)`
или запуск от root).

```bash
make install            # uv sync: .venv + зависимости (включая dev)
make run                # сервис пинга (инициализирует data/pinger.db)
make web                # веб на http://localhost:8000
```

Оба процесса должны смотреть в одну базу (`PINGER_DB`, по умолчанию
`data/pinger.db`).

## Переменные окружения

| Переменная            | Назначение                                             |
|-----------------------|--------------------------------------------------------|
| `PINGER_DB`           | путь к SQLite (по умолчанию `data/pinger.db`)          |
| `PINGER_LOG_LEVEL`    | уровень логирования сервиса (`INFO` по умолчанию)      |
| `SECRET_KEY`          | ключ подписи cookie-сессий веба                        |
| `PINGER_SETUP_TOKEN`  | необязательный токен для `/setup`                      |

В `docker-compose.yml` `SECRET_KEY` берётся из окружения
(`SECRET_KEY=... make docker-up`); в продакшене задайте свой секрет.

## Настройки (таблица `settings`)

| key                | по умолчанию | смысл                                     |
|--------------------|--------------|-------------------------------------------|
| `timeout_ms`       | `1000`       | `fping -t`: таймаут на пакет, мс          |
| `packets`          | `3`          | `fping -c`: пакетов на цель               |
| `interval_ms`      | `200`        | `fping -p`: интервал между пакетами, мс   |
| `round_interval_s` | `10`         | пауза между раундами опроса, с            |
| `ui_refresh_s`     | `5`          | период автообновления статусов (JSON), с  |
| `max_targets`      | `256`        | защитный лимит на размер батча            |

## Веб-интерфейс

- Фронтенд: Jinja2 + [Bootstrap 5.3](https://getbootstrap.com/) + HTMX, без
  сборки. Статика — `src/pinger/web/static/` (`bootstrap.min.css`,
  `htmx.min.js`, `status.js`, `app.css`, `app.js` — всё локально, без внешних
  CDN), отдаётся с `/static`. Компактная тёмная тема по умолчанию,
  переключатель ◐ в шапке (запоминается в `localStorage`).
- Главный экран — карточки страниц (сводка up/down, полоса доступности);
  карточка целиком кликабельна и открывает страницу, кнопок на карточках нет.
  У главного экрана два режима: `GET /` — просмотр, `GET /edit` —
  редактирование (только админ): создание страниц через модальное окно,
  переименование, описание, вкл/выкл и удаление.
- У каждой страницы **два режима**:
  - `GET /pages/{id}` — **просмотр**: таблица строк с цветными IP-чипами
    (зелёный — доступен, красный — нет, серый — данных ещё нет), uptime %
    за 24 ч у каждого адреса, сводка up/down. Форм изменения нет.
    Автообновление раз в `ui_refresh_s` секунд — не HTML-фрагментами, а через
    JSON: `GET /pages/{id}/status.json` и `GET /index.json` отдают срез
    статусов, `static/status.js` точечно обновляет DOM (чипы, uptime, сводки,
    полосы) без мигания; при изменении состава строк/страниц — полная
    перезагрузка. Поллинг паузится, когда вкладка скрыта.
  - `GET /pages/{id}/edit` — **редактирование**: добавление строк и адресов
    (через модальные окна), переименование/удаление строк, удаление адресов,
    включение-выключение адреса из опроса. Доступ — строго по праву
    редактирования (`user_page_edit`); без него режим просмотра read-only,
    а `/pages/{id}/edit` отвечает 403.
- Любое **добавление** (страница, строка, адрес, пользователь) — через
  модальное окно `<dialog>`, не через встроенные формы.
- Все изменения — через HTMX-фрагменты без перезагрузки; ошибки форм
  показываются на месте (диалог с ошибкой остаётся открытым), опасные
  действия требуют второго клика («Точно удалить?»), сетевые ошибки — тостом.
- `GET /addresses/{id}` — график доступности (интервалы up/down), uptime %,
  диапазоны 1 час / 12 часов / сутки / неделя / всё.

## Права доступа

- `admin` — все страницы, редактирование, управление пользователями.
- `user` — видимость по `access_mode`: `all` / `except` / `only`;
  редактирование — только страниц из списка «право редактирования»
  (и видимых). Создавать/удалять страницы нельзя.

## Состав проекта

```
src/pinger/
  __main__.py     # python -m pinger — сервис пинга
  db.py           # SQLite: подключение, схема, init
  settings.py     # настройки (key/value) с валидацией
  hosts.py        # CRUD pages / targets / addresses
  status.py       # host_status + закрытие интервалов host_events
  history.py      # интервалы и uptime % для экрана адреса
  fping.py        # запуск fping и парсинг вывода
  service.py      # цикл раундов, graceful shutdown
  web/            # FastAPI: маршруты, права, шаблоны, статика
tests/            # pytest: сервис, веб, права, история
Dockerfile        # образ с fping (uv + python 3.14)
docker-compose.yml# два сервиса на общей ./data
Makefile          # цели разработки и эксплуатации
```

## Тесты

- `tests/test_fping.py` — парсинг вывода fping и запуск (fake-fping).
- `tests/test_db.py`, `tests/test_settings.py` — схема, дефолты, WAL, каскады.
- `tests/test_status.py`, `tests/test_history.py` — интервалы, uptime.
- `tests/test_service.py` — раунды, переходы, shutdown.
- `tests/test_web_*.py` — auth/CSRF, права, CRUD, история, пользователи,
  автообновление, режимы просмотра/редактирования.

```bash
make test                                        # весь прогон
make test-one TEST=tests/test_fping.py           # один файл
make test-one TEST=tests/test_fping.py::test_parse_output_alive
```

## Публикация на GitHub

```bash
git init -b main            # если репозиторий ещё не инициализирован
git add .
git commit -m "pinger: сервис пинга fping + веб на FastAPI/HTMX"
git remote add origin git@github.com:<user>/pinger.git
git push -u origin main
```

В репозиторий не попадают: `data/` (база), `.venv/`, кэши — см. `.gitignore`.
Перед публикацией задайте в `docker-compose.yml`/CI свой `SECRET_KEY`.
